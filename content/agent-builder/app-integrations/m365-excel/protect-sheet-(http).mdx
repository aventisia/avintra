# Protect Sheet (HTTP)

The **Protect Sheet (HTTP)** node is used to secure an Excel worksheet within a file stored in OneDrive or SharePoint. This can be done with or without a password, making it a useful tool for safeguarding sensitive data from unauthorized changes.

**Key uses include:**

- Securing financial or business-sensitive information.
- Enforcing protection protocols on shared documents.
- Allowing read-only access while preventing editing.

## Configuration Options

| Field Name        | Description                                                                                      | Input Type | Required? | Default Value |
|-------------------|--------------------------------------------------------------------------------------------------|------------|-----------|---------------|
| **Tenant ID**     | Azure AD Tenant ID                                                                               | Text       | Yes       | _(empty)_     |
| **Client ID**     | Azure AD Client ID                                                                               | Text       | Yes       | _(empty)_     |
| **Client Secret** | Azure AD Client Secret                                                                           | Text       | Yes       | _(empty)_     |
| **Drive ID**      | OneDrive or SharePoint Drive ID                                                                  | Text       | Yes       | _(empty)_     |
| **File Path**     | The relative path to the Excel file in the drive (e.g., 'Reports/ProtectedSheet.xlsx').          | Text       | Yes       | _(empty)_     |
| **Worksheet Name**| The name of the worksheet to protect (e.g., 'Financials').                                       | Text       | Yes       | _(empty)_     |
| **Password (Optional)** | An optional password to protect the sheet. Leave blank for password-less protection.           | Text       | No        | _(empty)_     |

## Expected Output Format

The output is a confirmation message indicating the sheet has been successfully protected. The message does not include complex data or text formatting but confirms the success of the operation.

## Step-by-Step Guide

<Steps>
### Step 1

Add the **Protect Sheet (HTTP)** node to your workflow setup.

### Step 2

Enter your **Tenant ID**. This is your Azure Active Directory tenant ID.

### Step 3

Enter your **Client ID**. Make sure to use the correct client ID associated with your Azure AD application.

### Step 4

Enter your **Client Secret**. Keep this information secure as it acts as your password for Azure AD authentication.

### Step 5

Provide the **Drive ID** where the Excel file is stored. It's essential for locating the correct file.

### Step 6

Specify the **File Path** for the Excel file you wish to protect (e.g., 'Reports/ProtectedSheet.xlsx').

### Step 7

Enter the **Worksheet Name** you want to protect within the Excel file (e.g., 'Financials').

### Step 8

(Optional) Set a **Password** to add an extra layer of security. Without a password, the sheet will be protected without encryption.

### Step 9

Check the node output for a confirmation that the sheet has been protected.
</Steps>

<Callout type="info" title="Tip">
  Double-check the **File Path** and **Worksheet Name** to ensure correct references to the document and sheet you intend to protect.
</Callout>

## Common Mistakes & Troubleshooting

| Problem                                                       | Solution                                                                                                                                   |
|---------------------------------------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------|
| **Incorrect Tenant/Client ID**                                | Verify your Azure AD credentials. Ensure you're using IDs that are active and have the necessary permissions.                               |
| **Invalid File Path**                                         | Confirm the path format and check for typographical errors. Example format: 'Reports/ProtectedSheet.xlsx'.                                  |
| **Missing Password Message**                                  | If you want password protection, ensure the Password field is filled. Otherwise, it defaults to password-less protection.                   |

## Real-World Use Cases

- **Financial Reports**: Protect sensitive data in financial spreadsheets shared amongst team members to prevent unauthorized edits.
- **Inventory Lists**: Control editing permissions on inventory files circulated among various departments.
- **Project Plans**: Secure project plans to ensure that only authorized personnel can modify them, maintaining integrity of strategic plans.
