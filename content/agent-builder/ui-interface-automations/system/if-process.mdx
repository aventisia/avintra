# If Process

The **If Process** node allows you to evaluate whether a specific process on your computer is running or not. This node is highly useful in workflow automation because it lets you create conditional paths based on the status of processes, such as applications or system services. By using the **If Process** node, you can execute different actions depending on whether a selected process is active or inactive.

## Configuration Options

| Field Name   | Description                                                                                  | Input Type | Required? | Default Value |
| ------------ | -------------------------------------------------------------------------------------------- | ---------- | --------- | ------------- |
| **If process** (Condition) | The condition to evaluate: whether the process is **running** or **not running** on your system. | Select     | Yes       | _(empty)_     |
| **Process name** | The name of the process you want to check (e.g., Chrome, Visual Studio).                  | Select     | Yes       | _(empty)_     |
| **From User** | Toggle on to check if the process is running under a specific user account.                   | Switch     | No        | _(empty)_     |
| **User name** | The username to check against. This only applies if **From User** is enabled.                | Text       | No        | _(empty)_     |

## Expected Output Format

The output is a **Boolean value**, indicating whether the specified condition is met:

- `true`: The process condition you set (running or not) is met.
- `false`: The process condition is not met.

## Step-by-Step Guide

<Steps>
### Step 1

Add the **If Process** node to your automation flow.

### Step 2

In the **If process** field, select the condition you want to check:

- **Is Running**: To verify the process is currently active.
- **Is Not Running**: To verify the process is currently inactive.

### Step 3

In the **Process name** field, choose the process to evaluate from the dropdown list.

### Step 4

(Optional) If you need to specify a user, enable **From User**. Then fill in the **User name** with the relevant account name.

### Step 5

Continue setting up your workflow by configuring other nodes based on the output (`true` or `false`) from the **If Process** node.

</Steps>

<Callout type="info" title="Note">
  Ensure that you have the correct permissions to check processes running on your system, especially for processes that might require administrative rights.
</Callout>

## Input/Output Examples

| Condition   | Process Name | From User | User Name | Output  |
| ----------- | ------------ | --------- | --------- | ------- |
| Is Running  | Chrome       | No        | _(n/a)_   | `true`  |
| Is Running  | Idle         | Yes       | admin     | `false` |
| Is Not Running | Dllhost   | No        | _(n/a)_   | `true`  |

## Common Mistakes & Troubleshooting

| Problem                                         | Solution                                                                                               |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| **No output from node**                         | Check that the process name is correct and presently exists on your system.                            |
| **Permission denied errors**                    | Ensure you have the necessary permissions to check the status of the specified process.                |
| **Username not affecting output**               | Verify that **From User** is activated if checking against a specific username, and the name is correct.|

## Real-World Use Cases

- **Monitoring Applications**: Automatically launch or close applications based on whether they are already running.
- **System Checkpoints**: Implement checkpoints in scripts or services to run only if certain processes are active.
- **User-Specific Actions**: Trigger workflows specific to a user's context if they are running particular processes.
