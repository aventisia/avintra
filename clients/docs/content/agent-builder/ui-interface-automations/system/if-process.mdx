# If Process

The **If Process** node is used to start a sequence of actions based on whether a specific process on your computer is currently running. This is useful when you need your workflow to proceed differently depending on the activity status of certain applications or services.

For example:

- Checking if a crucial application like "Google Chrome" is currently active.
- Ensuring processes like "Visual Studio" are running before deploying code.
- Monitoring background services such as "Audio Device Graph" to ensure smooth media performance.

## Configuration Options

| Field Name       | Description                                                                         | Input Type | Required? | Default Value |
| ---------------- | ----------------------------------------------------------------------------------- | ---------- | --------- | ------------- |
| **Condition**    | Choose what condition to check (e.g., if the process is running or not).            | Select     | Yes       | _(empty)_     |
| **Process Name** | Select the name of the process you want to check.                                   | Select     | Yes       | _(empty)_     |
| **From User**    | Check this if you want to verify the process under a specific user account.         | Switch     | No        | _(empty)_     |
| **User Name**    | Enter the user name to check the process. _Appears only if "From User" is enabled._ | Text       | No        | _(empty)_     |

## Expected Output Format

The output of the **If Process** node does not produce a value itself but alters the execution flow based on the chosen condition.

## Step-by-Step Guide

<Steps>
### Step 1

Add the **If Process** node into your flow.

### Step 2

In the **Condition** dropdown, choose how you wish to check the process:

- **Is Running**: Checks if the specified process is currently active.
- **Is Not Running**: Checks if the specified process is inactive.

### Step 3

Select the process name from the **Process Name** dropdown that you want to evaluate.

### Step 4

If you would like the check to be specific to a user, toggle the **From User** switch.

### Step 5

If **From User** is enabled, enter the target user's name in the **User Name** field.

### Step 6

The flow will execute further actions based on whether the process meets the specified condition.

</Steps>

<Callout type="info" title="Note">
  The "User Name" field will only be active when "From User" is enabled. Ensure
  you want to specify a user before enabling it.
</Callout>

## Input/Output Examples

| Condition      | Process Name                          | From User | User Name | Execution Outcome                             |
| -------------- | ------------------------------------- | --------- | --------- | --------------------------------------------- |
| Is Running     | Google Chrome Browser                 | Yes       | johndoe   | Continues if Chrome is running under johndoe. |
| Is Not Running | Visual Studio Development Environment | No        | _(n/a)_   | Continues if Visual Studio is not running.    |

## Common Mistakes & Troubleshooting

| Problem                                   | Solution                                                                                                                |
| ----------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| **Process not found**                     | Ensure the correct process name is selected from the list. Check if the process is currently available.                 |
| **User-specific check not working**       | Verify that "From User" is enabled and the correct user name is entered. Ensure that the username is spelled correctly. |
| **Unexpected behavior in flow execution** | Double-check the selected condition and if it matches your intended logic (Is Running vs. Is Not Running).              |

## Real-World Use Cases

- **System Monitoring**: Automate alerts if critical processes like "Server Runtime" unexpectedly stop.
- **Resource Management**: Initiate resources only when specific applications are inactive to save system resources.
- **Security Checks**: Verify that security processes like "Intel Content Protection" are always active during secure transactions.
