# Get Checkbox Value

The **Get Checkbox Value** node is designed to retrieve the current state (checked or unchecked) of a checkbox element on a web page. Use this when you need to determine whether a specific checkbox is selected or not within your web automation workflow.

## Configuration Options

| Field Name               | Description                                                                                                         | Input Type | Required? | Default Value |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------- | ---------- | --------- | ------------- |
| **Web Browser Instance** | Enter or choose the variable that contains the web browser instance to work with.                                   | Text       | Yes       | _(empty)_     |
| **Find Type**            | Specifies how to find the element (e.g., ID, XPath, CssSelector). Choose from a wide variety of locator strategies. | Select     | Yes       | XPath         |
| **Value To Find**        | The value used to locate the element (e.g., `'username'`, `'//input[@id='email']'`).                                | Text       | Yes       | _(empty)_     |
| **Wait For Element**     | If true, waits for the checkbox to appear before retrieving the value.                                              | Switch     | No        | _(empty)_     |
| **Timeout Seconds**      | Maximum time in seconds to wait for the element before failing.                                                     | Text       | No        | 60            |

## Expected Output Format

The output of this node is a **boolean value** (`true` or `false`). The output indicates whether the checkbox is checked (`true`) or unchecked (`false`).

## Step-by-Step Guide

<Steps>
### Step 1

Add the **Get Checkbox Value** node into your flow.

### Step 2

In the **Web Browser Instance** field, enter or select the variable that holds the web browser session.

### Step 3

Select the method to find the checkbox element from the **Find Type** dropdown (e.g., XPath, CSS Selector, ID).

### Step 4

In the **Value To Find** field, input the exact value or selector necessary to locate your checkbox element.

### Step 5

(Optional) Toggle the **Wait For Element** switch if you want the flow to wait for the checkbox to appear before capturing its state.

### Step 6

(Optional) Define **Timeout Seconds** to set how long the flow should wait for the element in case it is not immediately available.

### Step 7

Retrieve the output as **IsChecked**. It will return `true` if the checkbox is checked, or `false` if it is unchecked.

</Steps>

<Callout type="info" title="Note">
  If the checkbox does not appear within the specified timeout, ensure that
  **Timeout Seconds** is appropriately set to a value that allows the element
  enough time to load.
</Callout>

## Common Mistakes & Troubleshooting

| Problem                       | Solution                                                                                                                           |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| **Element not found error**   | Double-check the **Value To Find** and ensure it correctly identifies the element on the page. Utilize subtle selectors as needed. |
| **Timeout occurs frequently** | Increase **Timeout Seconds** or ensure that **Wait For Element** is active to prevent premature timeout errors.                    |
| **Output not as expected**    | Validate that the locator and the input data match exactly to the intended page structure and element properties.                  |

## Real-World Use Cases

- **Subscription Management**: Check the state of a "Subscribe to Newsletter" checkbox to discern user preferences.
- **Form Validation**: Ensure that important confirmation checkboxes (e.g., terms and conditions) are checked before proceeding.
- **UI Testing**: Verify that default settings are accurately maintained or adjusted according to test scenarios in automated testing.
