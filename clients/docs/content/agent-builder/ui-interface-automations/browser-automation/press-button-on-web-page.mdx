# Press Button on Web Page

The **Press Button on Web Page** node is designed to mimic a click on a button on a web page. This can be incredibly helpful when automating web navigation or form submission tasks. It not only triggers the button's function but can also manage any resulting pop-up dialogs and wait for a new page to load if necessary.

This node is useful in scenarios where you need to interact with web forms, navigation menus, or any clickable elements to progress an automated workflow.

## Configuration Options

| Field Name                 | Description                                                                       | Input Type | Required? | Default Value |
| -------------------------- | --------------------------------------------------------------------------------- | ---------- | --------- | ------------- |
| **Web Browser Instance**   | Enter or choose the variable that contains the web browser instance to work with. | Text       | Yes       | _(empty)_     |
| **Find Type**              | Specifies how to find the element (e.g., ID, XPath, CssSelector).                 | Select     | Yes       | XPath         |
| **Value To Find**          | The value used to locate the element (e.g., 'username', '//input[@id='email']').  | Text       | Yes       | _(empty)_     |
| **Wait for Page Load**     | If true, waits for the next page to load after pressing the button.               | Switch     | No        | True          |
| **Timeout for Page Load**  | Maximum time in seconds to wait for the page to load.                             | Text       | No        | 60            |
| **Handle Dialog**          | Specifies what to do if a dialog appears after the click.                         | Select     | No        | DoNothing     |
| **Dialog Button to Press** | The name of the button to press if a dialog appears (e.g., 'Ok', 'Cancel').       | Text       | No        | Ok            |

## Expected Output Format

The output of this node does not produce any textual or numerical data; instead, it affects the browser state by interacting with web UI elements.

## Step-by-Step Guide

<Steps>

### Step 1

Add **Press Button on Web Page** node into your flow.

### Step 2

In the **Web Browser Instance** field, specify or choose the variable that represents your web browser session.

### Step 3

Select the **Find Type** in the dropdown based on how you want to locate the button on the web page:

- Options include XPath, ID, Class Name, Css Selector, and others based on HTML attributes or JavaScript expressions.

### Step 4

In the **Value To Find** field, enter the appropriate value that matches the selected Find Type (e.g., XPath path, element ID).

### Step 5

If you want to wait for the next page to load after the button is pressed, ensure the **Wait for Page Load** toggle is enabled.

### Step 6

Specify a **Timeout for Page Load** if needed. This sets how long to wait for the page to load before proceeding.

### Step 7

Configure **Handle Dialog** to automatically manage any pop-ups that appear after the click:

- Options include ignoring, closing, pressing buttons on, or accepting/dismissing alerts.

### Step 8

If pressing a button on a dialog, enter the **Dialog Button to Press**, such as 'Ok' or 'Cancel'.

</Steps>

<Callout type="info" title="Tip">
  For accurate element selection, ensure that the **Find Type** and **Value To
  Find** settings appropriately match the element's characteristics on the HTML
  page.
</Callout>

## Common Mistakes & Troubleshooting

| Problem                                     | Solution                                                                                                                                                         |
| ------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Element not found error**                 | Verify that the **Find Type** and **Value To Find** correctly match an element on the page, and check for any typos or inaccuracies in your values.              |
| **Timeout while waiting for page load**     | Increase the **Timeout for Page Load** value if the web page takes longer than expected to load. Ensure that the **Wait for Page Load** switch is set correctly. |
| **Dialog handling not working as expected** | Check if the **Handle Dialog** and **Dialog Button to Press** are correctly configured to correspond with the dialog's attributes and available options.         |

## Real-World Use Cases

- **Automated Form Submissions**: Automatically submit web forms by pressing the "Submit" button.
- **Navigation in Web Applications**: Simulate clicks on navigation menus to move between pages.
- **Interactive Tests**: Use this node to click through steps in automated browser testing scenarios.
- **Alert Management**: Avoid manual intervention by handling alerts through this automation.
