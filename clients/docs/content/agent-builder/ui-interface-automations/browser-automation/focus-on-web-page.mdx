# Focus on Web Page

The **Focus on Web Page** node enables you to direct attention to a specific text field within a web browser. By using this node, you can automate interactions with text inputs on web pages, ensuring the correct field has focus before input. It is particularly useful in automations involving data entry or interaction with web interfaces where precision is crucial.

For example:

- Ensuring the form field is focused before entering data.
- Automating repetitive tasks in a web application by navigating through fields.
- Handling unexpected dialogs or pop-ups that appear during web interactions.

## Configuration Options

| Field Name                 | Description                                                                  | Input Type | Required? | Default Value |
| -------------------------- | ---------------------------------------------------------------------------- | ---------- | --------- | ------------- |
| **Web Browser Instance**   | Enter or choose the variable that holds the web browser instance.            | Text       | Yes       | _(empty)_     |
| **Find Type**              | Specify the method to locate the text field (e.g., XPath, ID, CSS Selector). | Select     | Yes       | XPath         |
| **Value to Find**          | The identifier used to locate the element (like XPath, ID value).            | Text       | Yes       | _(empty)_     |
| **Wait for Page to Load**  | Decides if the process should wait for the web page to fully load.           | Switch     | No        | True          |
| **Timeout for Page Load**  | Maximum wait time (in seconds) for the page to load.                         | Text       | No        | 60            |
| **Handle Dialog**          | Action to perform if a dialog appears after focusing.                        | Select     | No        | DoNothing     |
| **Dialog Button to Press** | If handling dialogs with a button, sets the specific button to press.        | Text       | No        | Ok            |

## Expected Output Format

The use of this node does not generate an output value but focuses the specified text field on the webpage. It assists in streamlining further optional actions, assuming any dialog must be handled if set.

## Step-by-Step Guide

<Steps>
### Step 1

Add **Focus on Web Page** node into your flow.

### Step 2

In the **Web Browser Instance** field, enter the variable or select the instance representing your active browser session.

### Step 3

Determine how to locate the text field by setting the **Find Type** to options like XPath, ID, or CSS Selector.

### Step 4

Enter the element's criteria (e.g., XPath expression or ID) in the **Value to Find** field.

### Step 5

(Optional) Toggle on **Wait for Page to Load** if the field requires the web page to be fully loaded before interaction.

### Step 6

If enabled, adjust **Timeout for Page Load** to specify the maximum allowable wait period in seconds.

### Step 7

Choose behavior for potential pop-ups under **Handle Dialog** (such as close or ignore dialogs).

### Step 8

(Optional) Specify the button within the dialog to press in **Dialog Button to Press** if dialog handling involves a button press.

</Steps>

<Callout type="info" title="Tip">
  Ensure that the locator values (such as XPath or ID) are accurate and unique
  to prevent focus errors.
</Callout>

## Common Mistakes & Troubleshooting

| Problem                        | Solution                                                                                                                       |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------ |
| **Element not found error**    | Verify that the **Find Type** and **Value to Find** accurately refer to the desired element on the page.                       |
| **Page load timeout exceeded** | Increase the **Timeout for Page Load** value or ensure the page is accessible and optimized for loading within expected times. |
| **Dialogs not handled**        | Confirm that **Handle Dialog** is set appropriately, and **Dialog Button to Press** correctly identifies the target button.    |

## Real-World Use Cases

- **Data Entry Automation**: Refocus required fields for automation scripts entering data into forms or spreadsheets on the web.
- **Testing Web Apps**: Automate navigation and inputs during user acceptance testing of web applications.
- **Customer Support Portals**: Automatically navigate and interact with different fields within support interfaces for quick data entry and query resolution management.
