# Log Off User

The **Log Off User** node lets you automatically log off the current user from a desktop environment using different methods. This can be especially useful in scenarios where scheduled or remote log offs are needed to maintain security, save energy, or prepare devices for updates.

Common situations to use this node include:

- Logging off users at scheduled times to save energy.
- Preparing a system for updates by ensuring no users are logged on.
- Automating log offs in a shared device environment.

## Configuration Options

| Field Name        | Description                                                                  | Input Type | Required? | Default Value   |
| ----------------- | ---------------------------------------------------------------------------- | ---------- | --------- | --------------- |
| **Logoff Method** | Choose the method to log off the user.                                       | Select     | No        | ShutdownCommand |
| **Force Logoff**  | Enable this option to force a logoff if applications are not closing neatly. | Switch     | No        | Off             |

## Expected Output Format

The output of this node is the boolean value **Success**, indicating whether the logoff process was initiated successfully.

- **True** if the logoff was successful.
- **False** if the logoff process failed to initiate.

## Step-by-Step Guide

<Steps>

### Step 1

Add the **Log Off User** node into your automation flow.

### Step 2

In the **Logoff Method** dropdown, select the method you prefer to use for logging off:

- **Shutdown Command**: Uses the command-line tool.
- **Windows API**: Utilizes the ExitWindowsEx Windows API.
- **WTS API**: Uses the Terminal Services API.

### Step 3

Toggle **Force Logoff** to 'On' if you want to force the logoff even if applications are not responding.

### Step 4

Use the output value **Success** to determine if the logoff process started correctly for further automation steps.

</Steps>

<Callout type="warning" title="Important Note">
  Forced logoffs can result in unsaved data loss. Use this cautiously when
  automating log offs.
</Callout>

## Common Mistakes & Troubleshooting

| Problem                      | Solution                                                                                                 |
| ---------------------------- | -------------------------------------------------------------------------------------------------------- |
| **Logoff fails to initiate** | Ensure that your system allows the chosen method for logging off and that necessary permissions are set. |
| **Applications not closing** | Consider enabling **Force Logoff** if applications are not closing automatically during the logoff.      |

## Real-World Use Cases

- **Scheduled Log Offs**: Automatically log off users at the end of a workday for energy conservation.
- **Shared Workstations Management**: Ensure users are logged off from public access computers to maintain security.
- **Update Preparation**: Log off users in advance of scheduled system maintenance or updates to facilitate smoother processes.
