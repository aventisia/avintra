# Hash from File

The **Hash from File** node provides a way to create a unique fingerprint or hash for the contents of a file using common algorithms. This is useful for verifying file integrity, as hashes can confirm that files have not been altered.

Example usages include:

- Verifying that a downloaded file is complete and unaltered by comparing its hash against an expected value.
- Generating hashes for files before sending them over unsecured channels.
- Checking file integrity over time (e.g., in backup systems).

## Configuration Options

| Field Name            | Description                                                | Input Type | Required? | Default Value |
| --------------------- | ---------------------------------------------------------- | ---------- | --------- | ------------- |
| **File Path to Hash** | The path to the file you want to hash.                     | Text       | Yes       | _(empty)_     |
| **Hashing Algorithm** | The algorithm to use for hashing (SHA256, SHA512, or MD5). | Select     | Yes       | _(empty)_     |

## Expected Output Format

The output of this node is a **string representing the hashed content** of the file.

- Output will be a fixed-length string depending on the algorithm chosen:
  - **SHA256** produces a 64-character hash.
  - **SHA512** produces a 128-character hash.
  - **MD5** produces a 32-character hash.

## Step-by-Step Guide

<Steps>
### Step 1

Add the **Hash from File** node into your flow.

### Step 2

In the **File Path to Hash** field, enter the full path of the file whose contents you wish to hash.

### Step 3

Select a hashing method from the **Hashing Algorithm** dropdown menu. Options include SHA256, SHA512, or MD5, each offering different levels of hashing.

### Step 4

Once configured, the node will output the hash of the file as **HashedContent** for use in subsequent nodes.

</Steps>

<Callout type="info" title="Note">
  Ensure the file path is correct and accessible. If the file is moved or
  deleted, the node may not function as expected.
</Callout>

## Common Mistakes & Troubleshooting

| Problem                            | Solution                                                                                          |
| ---------------------------------- | ------------------------------------------------------------------------------------------------- |
| **Invalid File Path**              | Double-check the file path. Ensure it's correct and the file is accessible on your computer.      |
| **Empty Hash Result**              | Confirm that the file contains data to hash. An empty file will result in a hash without content. |
| **Different Hashes for Same File** | Ensure the same algorithm is used each time to maintain consistency across hash validations.      |

## Real-World Use Cases

- **Data Transfer**: Hash files before and after transfer for integrity checks.
- **Backup Systems**: Use hashes to verify files remain unchanged after backup restoration.
- **Security Audits**: Validate files periodically using hashes and note any unexpected changes.
