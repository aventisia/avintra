# Get Current Date and Time

The **Get Current Date and Time** node allows you to retrieve the current date and time based on specific retrieval options and time zones. This is particularly useful for timestamping activities, logging, or when dynamic date-time information is required in your workflow.

For example:

- Getting the current date and time for logging operations.
- Retrieving just the current date for calendar-related tasks.
- Adjusting date-time based on time zones for global applications.

## Configuration Options

| Field Name        | Description                                                                     | Input Type | Required? | Default Value   |
| ----------------- | ------------------------------------------------------------------------------- | ---------- | --------- | --------------- |
| **Retrieve Type** | Choose the type of date-time information you want (date and time or date only). | Select     | Yes       | CurrentDateTime |
| **Time Zone**     | Select the time zone to determine how the date and time are retrieved.          | Select     | Yes       | SystemTimeZone  |

## Expected Output Format

The output of this node, available as **Result**, will be a string representing the date and/or time based on the selected configuration:

- **CurrentDateTime**: Provides the complete current date and time (e.g., `2023-10-21T14:30:00`).
- **CurrentDateOnly**: Provides only the current date (e.g., `2023-10-21`).

## Step-by-Step Guide

<Steps>
### Step 1

Add **Get Current Date and Time** node into your workflow.

### Step 2

In the **Retrieve Type** dropdown, select the type of date-time information you need:

- **Current Date and Time**: Retrieves both current date and time.
- **Current Date Only**: Retrieves only the current date.

### Step 3

For the **Time Zone** dropdown, select the time zone preference:

- **System Time Zone**: Uses your system's current time zone.
- **Specific Time Zone**: Allows selection of a specific predefined time zone.
- **Windows Time Zone**: Aligns with Windows-specific time zones.
- **Custom Input**: Enables input of a custom time zone identifier.

### Step 4

The retrieved date and time will be stored in the **Result** field for further use in your workflow.

</Steps>

<Callout type="info" title="Note">
  Remember to verify the time zone settings might affect the output, especially
  if your system runs applications across different regions or requires precise
  timing.
</Callout>

## Common Mistakes & Troubleshooting

| Problem                              | Solution                                                                                                                                                                                |
| ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Incorrect Time Being Displayed**   | Ensure that your selected time zone matches your intended reference. Choosing **System Time Zone** will use your computer's local settings.                                             |
| **Fields Not Appearing as Expected** | Make sure to select the proper options in the dropdowns. Fields missing usually occur due to selection of **Custom Input** time zones without specifying the correct identifier format. |

## Real-World Use Cases

- **Event Scheduling**: Automatically generating current date and time stamps when scheduling events.
- **Timed Logs**: Capturing precise date-time stamps for error logging in systems.
- **Global Teams**: Adjusting to different time zones to sync tasks and deadlines within international teams.
- **Daily Reports**: Retrieving current date data for automatic generation of daily reports.
