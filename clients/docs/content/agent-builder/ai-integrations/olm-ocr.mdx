# Olm OCR

The **Olm OCR** node uploads a PDF file to a specified remote OCR (Optical Character Recognition) API and returns the text content extracted from the PDF in Markdown format. This is especially useful for converting scanned documents, invoices, or printed materials into editable text for further use in reports, analyses, or other digital workflows.

## Configuration Options

| Field Name        | Description                                      | Input Type | Required? | Default Value |
| ----------------- | ------------------------------------------------ | ---------- | --------- | ------------- |
| **API URL**       | URL of the OCR API endpoint.                     | Text       | Yes       | _(empty)_     |
| **PDF file path** | Path to the PDF file to be uploaded and OCR'd.   | Text       | Yes       | _(empty)_     |

## Expected Output Format

The output of this node is **OCR markdown output**, which will contain the extracted text from the PDF in Markdown format, labelled as `OcrText`.

## Step-by-Step Guide

<Steps>
### Step 1

Add the **Olm OCR** node into your flow.

### Step 2

In the **API URL** field, enter the endpoint URL for the remote OCR service you plan to use.

### Step 3

In the **PDF file path** field, provide the full path to the PDF file you want to upload and convert.

### Step 4

The node will process this information and return the extracted text in a Markdown format, available as **OcrText** for use in subsequent nodes.

</Steps>

<Callout type="info" title="Note">
  Ensure that the API URL is correct and accessible, and that the PDF file path is accurate to avoid connection errors or failed uploads.
</Callout>

## Common Mistakes & Troubleshooting

| Problem                                         | Solution                                                                |
| ----------------------------------------------- | ----------------------------------------------------------------------- |
| **Entered API URL is incorrect**                | Double-check the URL entered for typos or incorrect domain usage.       |
| **File not found at specified path**            | Ensure the file path is complete and the file exists at the specified location. |
| **OCR returns unexpected results**              | Verify that the PDF is clear and text is not skewed or obscured.        |

## Real-World Use Cases

- **Digitizing Business Documents**: Convert printed invoices into digital formats easily accessible for accounting software.
- **Data Extraction from Reports**: Extract text from scanned analytical reports to compile data or presentations.
- **Archiving**: Transform old documents into editable formats for long-term digital storage and quick retrieval.
