# Join Data Tables

The **Join Data Tables** node is designed to combine two data tables into a single table based on specified criteria. This is particularly useful for consolidating data sources or creating comprehensive views that require information from multiple tables.

For example:

- Combining customer information from different tables based on a common customer ID.
- Merging sales and customer data to analyze complete transactional records.

## Configuration Options

| Field Name            | Description                                            | Input Type | Required? | Default Value |
| --------------------- | ------------------------------------------------------ | ---------- | --------- | ------------- |
| **First Data Table**  | The first table you want to use in the join operation. | Text       | Yes       | _(empty)_     |
| **Second Data Table** | The second table you want to combine with the first.   | Text       | Yes       | _(empty)_     |
| **Join Operation**    | Choose the type of join: Inner, Left, or Full.         | Select     | Yes       | Inner         |
| **Join Rules**        | The condition to determine how tables will be joined.  | Text       | Yes       | _(empty)_     |

## Expected Output Format

The output is a **joined data table** presented as a single table combining rows from the specified tables according to the chosen join operation. The output is labeled **JoinedDataTable**.

## Step-by-Step Guide

<Steps>
### Step 1

Add **Join Data Tables** node into your flow.

### Step 2

In the **First Data Table** field, enter the name of the first table you want to join.

### Step 3

In the **Second Data Table** field, specify the second table to join with the first.

### Step 4

Select your preferred join operation from the **Join Operation** dropdown:

- **Inner Join**: Includes only the rows with matching values in both tables.
- **Left Outer Join**: Includes all rows from the first table and matched rows from the second table.
- **Full Outer Join**: Includes all rows when there is a match between tables.

### Step 5

Define the **Join Rules** to specify the logic for joining. For example, `FirstDataTable.ID = SecondDataTable.ID`.

### Step 6

The resulting combination of both tables will be output as **JoinedDataTable** for further use.

</Steps>

<Callout type="info" title="Tip">
  Ensure that the **Join Rules** accurately reference column names from both
  tables, maintaining consistent naming conventions to avoid errors.
</Callout>

## Input/Output Examples

| Join Operation | First Table | Second Table | Join Rule                         | Output Table                            |
| -------------- | ----------- | ------------ | --------------------------------- | --------------------------------------- |
| Inner          | Customers   | Orders       | Customers.ID = Orders.CustID      | Matched customer and order records only |
| Left           | Employees   | Departments  | Employees.DeptID = Departments.ID | All employees, matched departments      |
| Full           | Products    | Inventory    | Products.ID = Inventory.ProductID | All products and inventory items        |

## Common Mistakes & Troubleshooting

| Problem                                   | Solution                                                                              |
| ----------------------------------------- | ------------------------------------------------------------------------------------- |
| **Empty or incorrect output table**       | Check **Join Rules** for syntax errors or correct column referencing in both tables.  |
| **Invalid Join Operation selection**      | Ensure that your selected join operation matches your intended data merging strategy. |
| **Mismatched data types in join columns** | Ensure matching columns are of compatible data types in both tables.                  |

## Real-World Use Cases

- **Integrating Customer and Order Data**: Combine sales transactions with detailed customer profiles for CRM systems.
- **Consolidating Employee Records**: Merge employee personal data with HR departmental details for comprehensive reporting.
- **Analyzing Product and Inventory Levels**: Join tables to keep track of stock status alongside product specifications.
