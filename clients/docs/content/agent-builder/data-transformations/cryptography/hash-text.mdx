# Hash Text

The **Hash Text** node provides a way to securely transform text data into a fixed-size alphanumeric format using an algorithm of your choice. This is particularly useful when you need to store passwords, verify data integrity, or create digital signatures without exposing the actual data. Hashing ensures the privacy of the input text by converting it into an unreadable format.

For example:

- Store and verify passwords without keeping the actual password.
- Secure data by ensuring it hasn't been tampered with.
- Create a digital signature to prove authenticity of documents.

## Configuration Options

| Field Name            | Description                                                          | Input Type | Required? | Default Value |
| --------------------- | -------------------------------------------------------------------- | ---------- | --------- | ------------- |
| **Text to Hash**      | The original text you want to secure using hashing.                  | Text       | Yes       | _(empty)_     |
| **Hashing Algorithm** | Choose the algorithm to execute the hashing: SHA256, SHA512, or MD5. | Select     | Yes       | _(empty)_     |

## Expected Output Format

The output of this node is a **hashed alphanumeric string** that varies in length depending on the algorithm used:

- **SHA256**: Produces a 64-character long string.
- **SHA512**: Produces a 128-character long string.
- **MD5**: Produces a 32-character long string.

## Step-by-Step Guide

<Steps>
### Step 1

Add the **Hash Text** node into your process flow.

### Step 2

Enter the text you want to hash in the **Text to Hash** field.

### Step 3

From the **Hashing Algorithm** dropdown, select the desired algorithm:

- **SHA256**: A secure option for most needs.
- **SHA512**: Even more secure for sensitive data.
- **MD5**: A basic level of security for non-critical activities.

### Step 4

The hashed result will be output as **HashedText** for further use in other nodes or output processes.

</Steps>

<Callout type="info" title="Tip">
  Always choose a hashing algorithm according to your security needs: SHA
  algorithms are generally preferred for higher security than MD5.
</Callout>

## Common Mistakes & Troubleshooting

| Problem                   | Solution                                                                                     |
| ------------------------- | -------------------------------------------------------------------------------------------- |
| **Invalid Input**         | Ensure that the "Text to Hash" field contains text, not numbers or special characters alone. |
| **No Algorithm Selected** | Confirm that you have selected one of the provided hashing algorithms from the dropdown.     |

## Real-World Use Cases

- **Account Security**: Hash passwords before storing them in databases to protect user credentials.
- **File Integrity**: Generate a hash for files to ensure they haven't been altered during transfer.
- **Digital Signing**: Create unique digital signatures for documents to verify authenticity and origin.
