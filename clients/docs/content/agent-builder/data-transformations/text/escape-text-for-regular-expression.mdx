# Escape Text for Regular Expression

The **Escape Text for Regular Expression** node is designed to help you prepare text for use in regular expressions by escaping special characters. This is crucial when you need to ensure that characters like `*`, `+`, `?`, etc., are treated as literal text characters rather than regex operators. This node is particularly useful when constructing regex patterns dynamically and helps avoid syntax errors.

## Configuration Options

| Field Name         | Description                                                         | Input Type | Required? | Default Value |
| ------------------ | ------------------------------------------------------------------- | ---------- | --------- | ------------- |
| **Text to Escape** | The text value that will be escaped for use in regular expressions. | Text       | Yes       | _(empty)_     |

## Expected Output Format

The output of this node is a **single string of text** where special regex characters have been escaped. This ensures that the text is safe to use in a regular expression search or match operation.

## Step-by-Step Guide

<Steps>
### Step 1

Add **Escape Text for Regular Expression** node into your flow.

### Step 2

In the **Text to Escape** field, enter the text that contains characters you want to escape for regular expression usage.

### Step 3

The processed text, with special characters escaped, will be available as **EscapedText** for use in other nodes or processes.

</Steps>

<Callout type="info" title="Tip">
  Use this node when dynamically constructing regular expressions to prevent
  syntax errors from unescaped special characters.
</Callout>

## Input/Output Examples

| Input Text           | Output Value           | Output Type   |
| -------------------- | ---------------------- | ------------- |
| `sample.text*`       | `sample\.text\*`       | String (Text) |
| `abc[123]`           | `abc\[123\]`           | String (Text) |
| `match this (maybe)` | `match this \(maybe\)` | String (Text) |

## Common Mistakes & Troubleshooting

| Problem                                 | Solution                                                                                                               |
| --------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| **No output or empty result**           | Ensure that the **Text to Escape** field is not empty. If it is, there will be nothing to escape.                      |
| **Unexpected characters being escaped** | Double-check the input text for accidental inclusion of characters not meant to be escaped.                            |
| **Text not escaped as needed**          | Be sure the input text contains characters that require escaping for use in regular expressions (e.g., `*`, `+`, `.`). |

## Real-World Use Cases

- **Search Query Construction**: Ensure user input in search forms does not break the underlying regex logic due to special characters.
- **Dynamic Pattern Building**: Escape special characters when generating regex patterns programmatically.
- **Text Sanitization for Scripts**: Avoid issues in scripts that utilize regex for text processing by pre-escaping required characters.
