# Reply to Email

The **Reply to Email** node allows you to send a response to an existing email by using its unique Message ID. This is particularly useful when you need to automate email replies within a specified corporate mailbox. You can use this node to streamline communication, manage responses efficiently, and maintain a record of interactions within an established message thread.

## Configuration Options

| Field Name             | Description                                                    | Input Type | Required? | Default Value |
| ---------------------- | -------------------------------------------------------------- | ---------- | --------- | ------------- |
| **Message ID**         | The unique identifier of the email you want to reply to.       | Text       | Yes       | _(empty)_     |
| **Reply Message JSON** | A JSON string that describes the reply content and structure.  | Text       | Yes       | _(empty)_     |
| **User Email**         | The email address owning the mailbox from which to send reply. | Text       | Yes       | _(empty)_     |
| **Tenant ID**          | The Azure AD Tenant Directory ID.                              | Text       | Yes       | _(empty)_     |
| **Client ID**          | The Azure AD Application (Client) ID.                          | Text       | Yes       | _(empty)_     |
| **Client Secret**      | The confidential Azure AD Application Client Secret.           | Text       | Yes       | _(empty)_     |

## Expected Output Format

The node does not produce a visible output after sending an email reply; it performs the action of sending an email reply based on the provided input configurations.

## Step-by-Step Guide

<Steps>
### Step 1

Add the **Reply to Email** node to your workflow from the node list.

### Step 2

In the **Message ID** field, enter the ID of the message you wish to reply to. This is crucial for identifying the specific thread.

### Step 3

Input the **Reply Message JSON**. Ensure the JSON accurately represents your reply's content, including subject and body if necessary.

### Step 4

In the **User Email** field, provide the email address associated with the account sending the reply.

### Step 5

Fill in the **Tenant ID** with your Azure Active Directory Tenant ID.

### Step 6

Provide the **Client ID** related to your Azure AD Application.

### Step 7

In the **Client Secret** field, input your Azure AD Application Client Secret. This is required for authentication and authorization of email sending actions.

</Steps>

<Callout type="warning" title="Important">
  Verify the **Reply Message JSON** format before submission to avoid errors or
  sending unintended replies.
</Callout>

## Input/Output Examples

### Input Example

- **Message ID**: `1234567`
- **Reply Message JSON**: `{"subject": "Re: Meeting Update", "body": "Thank you for the update."}`
- **User Email**: `user@example.com`
- **Tenant ID**: `abcdefg-1234-5678-hijk-9876543210lm`
- **Client ID**: `abcd1234-efgh-5678-ijkl-0987654321mn`
- **Client Secret**: `abcdef123456ghijklmnop789`

### Output

- The node sends an email reply based on the inputs but does not display a specific output within the platform.

## Common Mistakes & Troubleshooting

| Problem                                            | Solution                                                                                                                  |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| **Invalid Message ID**                             | Ensure that the Message ID corresponds to an existing email within the mailbox. Check that no typographical errors exist. |
| **Incorrect JSON Format for Reply Message**        | Validate the JSON string. Use online JSON validators to ensure proper syntax before entering it into the field.           |
| **Authentication Failure due to Client ID/Secret** | Double-check the Azure AD Client ID and Client Secret values for accuracy. Verify your Azure credentials are up-to-date.  |

## Real-World Use Cases

- **Automated Meeting Confirmations**: Respond to meeting invites automatically based on inbox queries.
- **Customer Support**: Use reply automation in a customer support system to send responses based on pre-defined conditions.
- **Email Thread Management**: Maintain email threads efficiently by replying to emails automatically in workflow systems utilizing business rules.
