# Create AWS ELB Load Balancer

The **Create AWS ELB Load Balancer** node facilitates the creation of a Load Balancer in AWS. This Load Balancer can either be an Application Load Balancer (ALB) or a Network Load Balancer (NLB). It helps distribute incoming application traffic across multiple targets, such as Amazon EC2 instances, thus improving fault tolerance and enhancing application availability.

You might use this node to:

- Manage traffic to your web applications efficiently.
- Ensure high availability of your application by balancing incoming requests to healthy resources.
- Automatically scale your load balancing capacity according to traffic demands.

## Configuration Options

| Field Name                     | Description                                                                | Input Type | Required? | Default Value |
| ------------------------------ | -------------------------------------------------------------------------- | ---------- | --------- | ------------- |
| **Credential to connect with** | Select the AWS credential to use for authentication.                       | Text       | Yes       | _(empty)_     |
| **IP Address Type**            | Specify the IP address type of the load balancer.                          | Select     | Yes       | _(empty)_     |
| **Name**                       | Enter the name of the load balancer.                                       | Text       | Yes       | _(empty)_     |
| **Schema**                     | Specifies whether the load balancer is internal or internet-facing.        | Select     | Yes       | _(empty)_     |
| **Type**                       | Specify the type of load balancer (Application or Network).                | Select     | Yes       | _(empty)_     |
| **Subnet ID Names or IDs**     | List the subnet IDs where the load balancer will be deployed.              | Text       | Yes       | _(empty)_     |
| **Additional Fields**          | Optional tags to attach to the load balancer (key-value pairs).            | Text       | No        | _(empty)_     |
| **AWS Region**                 | The AWS region where the load balancer is located. Default is `us-east-1`. | Text       | No        | _(empty)_     |

## Expected Output Format

The node will provide three key pieces of information after successfully creating a load balancer:

- **Load Balancer ARN**: A unique identifier for the load balancer.
- **DNS Name**: The DNS name for accessing the load balancer.
- **API Response**: A raw JSON response from AWS, providing additional creation details.

## Step-by-Step Guide

<Steps>
### Step 1

Add the **Create AWS ELB Load Balancer** node into your workflow.

### Step 2

Enter the required **Credential** to connect with AWS in the field provided.

### Step 3

Select the **IP Address Type** from the dropdown list: `Ipv4` or `Ipv6`.

### Step 4

Input a **Name** for your load balancer to identify it.

### Step 5

Choose the **Schema** for your load balancer: `Internal` for within a VPC or `Internet-facing` for public access.

### Step 6

Decide the **Type** of load balancer either `Application` or `Network`.

### Step 7

Enter the **Subnet ID Names or IDs** to specify where the load balancer will be deployed.

### Step 8

Optionally, add **Additional Fields** as key-value pairs to attach tags to your load balancer.

### Step 9

Specify the **AWS Region** for your load balancer, if different from the default `us-east-1`.

### Step 10

The system will generate outputs: **Load Balancer ARN**, **DNS Name**, and **API Response** for further integration or monitoring.

</Steps>

<Callout type="info" title="Tip">
  Make sure your AWS credentials have the necessary permissions to create and
  manage load balancers.
</Callout>

## Common Mistakes & Troubleshooting

| Problem                            | Solution                                                                                 |
| ---------------------------------- | ---------------------------------------------------------------------------------------- |
| **Invalid AWS credentials**        | Ensure the credentials entered are valid and have permissions to create a load balancer. |
| **Missing required information**   | Check that all required fields are completed, such as Name, Subnet IDs, and Type.        |
| **Incorrect AWS region specified** | Ensure the AWS region specified matches available regions for your AWS account.          |

## Real-World Use Cases

- **Web Application Traffic Distribution**: Manage incoming web requests across multiple instances for a media application.
- **E-commerce Platform**: Balance loads for a shopping website to ensure no server is overwhelmed during sales events.
- **Redundancy and Failover**: Use load balancers to redirect traffic in case of service failures in one region, maintaining service availability.
