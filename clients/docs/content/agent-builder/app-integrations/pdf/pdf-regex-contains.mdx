# PDF Regex Contains

The **PDF Regex Contains** node is used to check if a PDF document contains text that matches a specific regular expression pattern. This is particularly useful when you need to conduct case-sensitive searches within a PDF file, such as verifying the presence of certain terms, phrases, or formats.

Imagine you are looking to confirm if an automated report or form includes specific keywords or identifiers - this node can simplify such validations by automatically searching PDFs for matching patterns.

## Configuration Options

| Field Name        | Description                                                                          | Input Type | Required? | Default Value |
| ----------------- | ------------------------------------------------------------------------------------ | ---------- | --------- | ------------- |
| **PDF File Path** | The full path to the PDF file to search (e.g., C:\docs\document.pdf).                | Text       | Yes       | _(empty)_     |
| **Regex Pattern** | The regular expression used to search for text within the PDF. It is case-sensitive. | Text       | Yes       | _(empty)_     |

## Expected Output Format

The node generates a **boolean value** indicating whether the pattern was found:

- **True** if the specified regex pattern matches text within the PDF.
- **False** if no matches are found.

## Step-by-Step Guide

<Steps>
### Step 1

Add the **PDF Regex Contains** node into your workflow.

### Step 2

In the **PDF File Path** field, enter the full path to the PDF file you wish to search. Make sure the file path is correct and accessible.

### Step 3

Enter the desired **Regex Pattern** into the respective field. This pattern needs to be the exact regular expression you are seeking within the document.

### Step 4

Once configured, the node will output **True** if any text in the PDF matches the regex pattern, and **False** if there are no matches.

</Steps>

<Callout type="info" title="Tip">
  Use a regex testing tool to refine and test your regular expressions before
  applying them in this node.
</Callout>

## Input/Output Examples

| PDF File Path          | Regex Pattern          | Output Value | Output Type |
| ---------------------- | ---------------------- | ------------ | ----------- |
| `C:\docs\document.pdf` | `Name:\\s*\\w+`        | True         | Boolean     |
| `C:\docs\report.pdf`   | `Invoice\\s*:\\s*\\d+` | False        | Boolean     |

## Common Mistakes & Troubleshooting

| Problem                                      | Solution                                                                  |
| -------------------------------------------- | ------------------------------------------------------------------------- |
| **Incorrect file path**                      | Ensure the file path is accurate and the PDF file is accessible.          |
| **Regex pattern not matching expected text** | Verify the regular expression is correct and consider case sensitivity.   |
| **Unexpected output (always False)**         | Double-check the file path and ensure the PDF is not encrypted/protected. |

## Real-World Use Cases

- **Document Verification**: Automatically verify that regulatory or compliance reports include specific legal disclaimers.
- **Form Processing**: Confirm entries or codes are present in digitally filled forms.
- **Data Extraction Validations**: Ensure scanned invoices contain specific product codes or specific identifiers.
