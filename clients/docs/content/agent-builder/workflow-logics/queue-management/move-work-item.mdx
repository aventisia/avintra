# Move Work Item

The **Move Work Item** node facilitates the transfer of a work item from one queue to another within your system. This node is typically used in workflow automation to efficiently handle tasks by reassigning work items based on their status, priority, or other criteria.

For example:

- Transferring tasks to a different department's queue for further action.
- Reorganizing pending items based on updated priorities.
- Allocating resources by moving items between queues.

## Configuration Options

| Field Name         | Description                                                     | Input Type   | Required? | Default Value |
| ------------------ | --------------------------------------------------------------- | ------------ | --------- | ------------- |
| **WorkItem ID**    | Enter the unique identifier of the work item you want to move.  | Text         | Yes       | _(empty)_     |
| **Select Queue**   | Choose the destination queue where the work item will be moved. | Queue Select | Yes       | _(empty)_     |
| **Work Item Data** | Provide the data payload for the work item in JSON format.      | JSON Editor  | Yes       | _(empty)_     |
| **Remark**         | Enter a remark for the work item, optional.                     | Text         | No        | _(empty)_     |

## Expected Output Format

The output is a **boolean value** indicating the success of the operation.

- If the work item is moved successfully: output will be `true`.
- If the move fails due to any issue (such as invalid input or system error): output may not be `true`.

## Step-by-Step Guide

<Steps>
### Step 1

Add the **Move Work Item** node into your workflow.

### Step 2

In the **WorkItem ID** field, enter the unique identifier of the work item you wish to move. This ID is crucial for identifying the specific item in the source queue.

### Step 3

In the **Select Queue** dropdown, choose the destination queue. This selection determines where the work item will be moved.

### Step 4

In the **Work Item Data** section, provide additional data for the work item in JSON format. This data travels with the work item.

### Step 5

(Optional) Enter any remarks about the move in the **Remark** field. These notes can help document the reason or context of the move.

### Step 6

The operation outputs the result as **MovedWorkItem**, indicating success (`true`) or failure.

</Steps>

<Callout type="info" title="Note">
  Ensure all required fields like **WorkItem ID** and **Select Queue** are
  populated correctly before executing the node to prevent errors.
</Callout>

## Common Mistakes & Troubleshooting

| Problem                                  | Solution                                                                                                             |
| ---------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| **Input fields not filled correctly**    | Ensure that all mandatory fields like **WorkItem ID** and **Select Queue** are correctly filled in to avoid errors.  |
| **Incorrect queue selected**             | Double-check the destination queue to ensure it matches the requirement for the work item's next step in processing. |
| **JSON format errors in Work Item Data** | Verify the JSON data for errors such as missing brackets or quotation marks to ensure it is correctly formatted.     |

## Real-World Use Cases

- **Claim Management**: Move insurance claims to different processing queues based on the documentation completeness.
- **Task Reallocation**: Automatically shift tasks between team queues for workload balancing.
- **Customer Support**: Redirect support tickets to more specialized queues as determined by ticket tags or content analysis.
