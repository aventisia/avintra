# Agents list and folders

Build > Agents shows a folders shelf above the agents that are not in a folder. Folders are one level deep, shared in the space, and belong to the backend `FoldersTable` feature.

- The page is built on the client from the two agent lists (`["flows", space]`, `["flows", "SHARED", space]`) and the folders list (`["folders", space]`). The shelf sits outside the agents table, so folders never count toward agent paging and every folder stays visible as a drop target. The table holds agents only; its page is kept after a move, edit or delete and resets only when the search text or the page size changes.
- The agents list is a TableCN table (`useAgentsTable`, see `packages/ui/src/components/table-cn/README.md`). Its page, page size, sorting and filters are kept in the URL (`page`, `perPage`, `sort`, one parameter per filter), so they survive reloads and the back button. Each route has its own, so opening a folder starts at page 1. Column visibility and the last sorting are remembered per browser under `table-cn:flows`. Grid and table views share the table instance, so they show the same page, filters and sorting.
- The toolbar (search, filters, sort, view options) sits under the page header, above the folders shelf, so it does not move while the shelf hides during a search. Filters are Type, Platform and Access; the access options come from the listed agents. An agent is archived when its latest version is archived. Archived agents are hidden; the Archived toggle beside Sort (with their count, kept in the URL as `archived=1`) shows only them, muted in the table and badged on cards. The two list requests pass `includeArchived`, since the API leaves archived agents out by default. Filters narrow the agents of the current level only: on the main page they do not pull in agents from folders (search does).
- The name column has two lines: the name (and folder chip while searching), then its version, the Published badge (published agents only), how long ago it was updated and linked queues; other columns stay on one line. Empty values are left out, not shown as placeholders. The Select Row, Created On and Access columns are hidden by default (Select Row is toggled from View; Access keeps its filter). There is no Updated On column; the update time is the later of the agent's and its latest version's edit.
- Selecting agents (table view; Shift+click selects a range) opens the action bar: Move to (top level or a folder, through `useMoveFlowToFolder().moveFlows`; agents the user cannot edit are skipped, and a partial failure says how many moved), Export CSV (CSV of the selected rows' visible columns), and Delete.
- Each agent's actions menu (table row and grid card, top level and inside a folder) has Export when the user can read it (Owner, Edit, or View). It fetches the version Open would show (`GET flow/load/{flowId}` via the `flow-builder` feature, which mirrors the backend `FlowBuilderController`) and downloads it as `<Agent name>_v<version>_YYYY-MM-DD_HH-mm-ss.json` (local time) with canvas, flow variables and inputs/outputs nested in `reactFlowObject` (`hooks/useExportFlow.hook.ts`, `utils/flow-export.util.ts`), the same shape the Studio's Export writes; a success toast confirms; a failure shows one error toast and nothing is downloaded. The item is disabled while that agent's export is in flight.
- The same menu offers Archive, or Unarchive while the agent is archived, to the agent's creator and to anyone who owns it or has Edit access (`getResourceAccessActions().update`), the shared rule for writing to an agent. Archive asks first, says that queues, triggers, machines and shared resources are detached and are not restored on unarchive, and then archives the agent's latest version and its other unarchived versions in one request (`useArchiveFlowVersionsMutation`). An agent with an unarchived published version cannot be archived: the confirmation is replaced by an explanation dialog, and if the list's Published badge only reflects the latest version, the server refuses with the same explanation. Unarchive also asks first and puts the agent's archived versions back, without reattaching anything. Both refresh the agents lists and the folders, so the Archived toggle, its count, the folder counts, the card badge and the muted table rows follow; the server still refuses to execute an archived agent.
- The shelf can be collapsed (remembered per user in `localStorage`); it opens by itself while an agent is dragged.
- Search matches names only. It filters the shelf (hidden when no folder matches) and includes agents inside folders, which then carry a clickable folder chip. Without search, agents in a folder are listed only on its folder page.
- Folder counts follow the Archived toggle: archived agents while it is on, active agents otherwise. The delete dialog uses the server count, which includes agents the user cannot see, and says how many of those there are.
- An agent whose folder is not in the folders list (stale cache) is treated as top level.
- Folder colors come from a fixed palette (`FOLDER_COLORS`). A folder stores the key of its chosen color; the create dialog preselects a random one (`getRandomFolderColor`). `getFolderColor` falls back to a color derived from the folder id when none is stored or the key is unknown, so folders created before colors were saved keep their look.
- Folder dialogs (create/edit, delete, move agent) are centered card dialogs in the agent access style. Create and edit are the `folder` entity of the URL-driven CRUD dialog (`FolderCrudDialog`, registered in `WorkspaceCrudDialogProvider` like `flow`), opened with `useFolderFormDialog` from any route. Like the agent dialog they reopen after a refresh with fresh values (create empty with a new random color, edit with the saved values) and warn about unsaved changes on close, in-app navigation and browser unload. The agent to move into a new folder (drop on "New folder") is handed to the dialog through `useFolderDialogStore` and taken out once it opens, so a refresh or Back reopens it as a plain create. An edit whose folder is gone shows "Folder not found" once and closes. Delete and move agent are opened through `useFolderDialogStore` and mounted once per page by `FolderDialogs`. Create and edit wait for the server, so a new folder appears with its real id; the name is checked against the loaded folders as the user types (trimmed, case-insensitive, like the server).
- Share (row action) opens the shared `ResourceUserAccessDialog` from `features/resource-user-access`, the card dialog every shareable resource uses (its shell, buttons and status line live in `components/card-dialog`). Changes (Specific people or Everyone, people added, role changes, removals) stay in a draft (`useResourceUserAccessDraft`) and are sent together on Save changes; a partial failure keeps the dialog open with the remaining changes. The user's own row is locked, and Everyone gives view access only. Spaces offer neither Everyone nor roles.
- Move paths, all through `useMoveFlowToFolder`: the bulk action bar, drag onto a folder tile (or onto the "Agents" breadcrumb on a folder page), drag onto "New folder" (creates the folder, then moves the agent), the Move agent dialog (top level, any folder, or a new folder named after the search), and "Remove from folder". The hook updates both agent query keys at once and restores them on error. Only agents the user owns or can edit are movable; the server checks the same rule on `PUT flow/folder`.
- Drag and drop is native HTML5 with a custom MIME type, so links, files and text dropped on a folder are ignored. The dragged agent is mirrored in `useAgentDragStore` so targets can show they accept it; a compact drag image is rendered by `AgentsListView`. The Move agent dialog is the keyboard path.
- Folder page route: `/agents/folders/:folderId`, remounted per folder. A folder that is not found (deleted elsewhere, other space) or whose folders list fails to load redirects to `/agents` with one error toast. Deleting the open folder leaves the page before the lists refresh. The create agent dialog reads the folder from the route (`useMatch`) because it is mounted above the routed page.
- `PUT flow` cannot change an agent's folder; only `POST flow` (create) and `PUT flow/folder` can.
